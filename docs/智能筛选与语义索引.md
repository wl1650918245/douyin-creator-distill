# 智能筛选与语义索引

## 1. 目标

用户可以在已审核的作品目录中输入一句自然语言，例如“普通人如何赚钱”或“关于 Skill 的内容”，从作品标题、简介和已有转写中召回语义相关作品。独立的“智能检索”页面还可以跨多个关注博主、收藏夹和其他已索引作品资产搜索。普通搜索全部在本机执行，不消耗分析模型 API。

## 2. 输入与优先级

每条作品的索引文本由以下材料组成：

1. 作品标题。
2. 作者发布时填写的作品简介。
3. 已完成的转写正文；同一作品同时存在本地 Whisper 和云端文本时，优先使用本地 Whisper。

转写正文按约 1200 个字符分段，相邻分段保留约 120 个字符重叠。标题和简介会附加到每个正文分段，避免局部片段丢失作品主题。

## 3. SQLite 表

`semantic_documents` 保存作品当前参与索引的材料状态：

- 唯一键：`source_key + video_id`。
- `title`、`description`：当前标题和简介。
- `transcript_path`：实际使用的转写文件路径，可为空。
- `content_hash`：规范化后的标题、简介与正文 SHA-256。

`semantic_embeddings` 保存可重建向量：

- 唯一键：`source_key + video_id + model_id + chunk_index`。
- `content_hash`：生成当前向量时的材料版本。
- `dimension`、`embedding`：向量维度和二进制浮点数据。
- `text_excerpt`：命中后可追溯的片段摘要。

内容哈希不是作品身份。作品身份始终由来源和平台作品 ID 决定；哈希只用于判断材料是否变化。

## 4. 增量更新

用户点击“建立索引”或“更新索引”后，系统逐条计算当前材料哈希：

- 哈希、模型和分段数都未变化：直接复用已有向量。
- 标题、简介或转写发生变化：只删除并重算该作品在当前模型下的向量。
- 切换轻量或高精度模型：为新模型建立独立索引，不覆盖旧模型索引。
- 任务中断：已经写入 SQLite 的分段保留；再次更新时会复用完整作品并补算未完成作品。

索引任务进入任务中心，展示进度、完成状态或失败原因。索引不会自动调用外部模型。

## 5. 搜索与精排

本地搜索把查询编码为向量，与当前目录、当前模型下的作品分段计算余弦相似度；每条作品取最高分片段，按相关度排序并联动内容列表。

跨来源检索使用相同的本地模型和相似度算法，但检索范围由 `source_key` 集合决定：

- 不限定来源时，搜索当前模型下已经建立索引的全部作品资产。
- 用户可以只勾选一个或多个关注博主、收藏夹来源。
- 结果按 `source_key + video_id` 聚合，避免不同来源中相同作品 ID 互相覆盖。
- 每条结果返回来源、作品标题、简介、命中证据片段和原作品链接。

这里的“全部知识资产”仅指已经写入当前语义索引的作品材料，不包含尚未索引的分析报告、选题和智能体画像。

“精排复核”是单独的显式操作：

- 只把本地召回的前 20 个候选及其证据片段发送给 `config/model.config.json` 配置的分析模型。
- 页面不读取或显示 API 密钥。
- 未点击“精排复核”时不会产生外部模型请求或费用。

## 6. 已验证证据

- 轻量模型 `bge-small-zh-v1.5` 已离线输出 512 维中文向量。
- 高精度模型 `Qwen3-Embedding-0.6B` 已离线输出 1024 维中文向量。
- 2026-08-04，姜胡说最新目录 645 条作品完成索引。索引按来源资产账本复用历史转写正文，共形成 3,419 个语义片段；第二次更新复用 645 条、重算 0 条。
- “普通人如何赚钱”和“Skill 知识蒸馏”均召回主题相关作品；Playwright 验证搜索结果会真实联动作品目录。
- 2026-08-06，独立智能检索页读取姜胡说和飞天闪客两个真实来源，共 726 条作品、3,520 个片段；跨来源 API 和 Playwright 页面查询均返回带来源名称的真实结果。

以上只证明当前本机与当前材料已跑通，不承诺所有查询都达到相同准确率。低相关结果可切换高精度模型或由用户显式执行精排复核。
