# 关注与更新

## 1. 两类关注来源

“关注与更新”管理两种不同来源：

- `creator`：公开博主主页，以提交的抖音号或主页来源作为稳定键。
- `favorites`：当前收藏夹账号，以项目内 `profileId` 作为稳定键。

“我的收藏夹”不是关注博主。页面可以统一管理两类增量来源，但必须明确显示来源类型。历史任务中的显示名称、乱码名称或首条作品作者名都不能作为收藏夹身份键。

## 2. 收藏夹目录缓存

收藏夹子文件夹目录保存在 SQLite 的 `favorites_directory_cache` 中：

- 缓存键：收藏夹账号的项目内 `profileId`。
- 缓存内容：收藏夹 ID、名称、作品数、证据 JSON 路径和刷新时间。
- 默认有效期：24 小时。
- 有效期内打开“抓取我的收藏夹”时直接显示缓存，不启动 Chrome。
- 用户点击“刷新收藏夹目录”或缓存过期时，才重新访问平台目录接口。

目录缓存只用于快速展示可选文件夹，不能证明文件夹内作品仍是最新状态。用户确认抓取或定时检查时，仍需读取所选收藏夹的作品并按 `videoId` 去重。

## 3. 订阅状态

SQLite 的 `subscriptions` 表保存更新规则，不保存作品正文：

- 来源类型、稳定来源键、显示名称。
- 使用的账号角色和 `profileId`。
- 收藏夹选择范围。
- 是否启用、检查间隔、下次检查时间。
- 最近检查、最近成功、错误和增量结果。
- 最近一次审核通过目录的基线路径。

取消关注采用软删除，只移除更新规则。已有 JSON、转写文本、分析报告和任务历史继续保留。重新手动抓取同一来源后，可以再次建立关注规则。

## 4. 定时执行边界

- 本地服务运行时，每分钟检查一次是否存在到期规则。
- 每条规则默认每天检查一次，并增加少量随机延迟。
- 所有检查进入现有目录抓取串行队列；同一规则不能同时存在两个活动任务。
- 公开博主自动检查先读取最近一次审核通过的作品 ID 基线，只滚动近期作品；进入稳定的历史重叠区后停止。
- 自动检查只追加新作品，不周期性删除历史作品，也不要求累计资产数始终等于当前主页计数。
- 用户点击“重新抓取”时仍执行全量快照和严格数量审核，用于需要时人工重建基线。
- 定时检查只抓取和审核目录，不自动转写、拆解或蒸馏。
- 只有 JSON 审核通过才更新增量基线；失败或待复核不会推进基线。
- 首版调度器依赖本地服务进程。关闭服务后不会后台执行；开机自启或 Windows 任务计划属于后续独立能力。

## 5. 页面操作

每个关注来源支持：

- 打开最新作品目录。
- 立即检查。
- 暂停或恢复定期更新。
- 设置 6 小时、12 小时、每天或每周检查。
- 取消关注，但保留历史资产。
