# 状态表迁移方案

## 1. 范围

本次迁移是增加式迁移，不删除 `tasks`、`crawl_runs`、`transcript_jobs`、订阅记录或任何本地文件。

## 2. 新表

- `works`：作品总账。
- `crawl_run_works`：抓取版本与作品的证据关系。
- `work_processing_state`：每个作品每个处理阶段的当前状态。
- `artifacts`：本地产物索引。
- `task_checkpoints`：任务恢复检查点。

## 3. 回填顺序

1. 读取审核通过的 `crawl_runs.output_path`。
2. 按任务上下文生成 `source_key`。
3. 将 JSON 中作品按 `source_key + video_id` 写入 `works`。
4. 写入 `crawl_run_works` 和 JSON 产物索引。
5. 扫描 `transcript_jobs`，按同一作品全部历史任务聚合状态。
6. 已存在任意成功转写时，作品转写状态固定为 `completed`。
7. 登记 Markdown、原始响应、SRT 和 manifest 文件路径。

## 4. 回滚

新表只提供统一索引。出现问题时可以停止读取新表，旧 JSON 和任务表仍保持完整。不得通过回滚删除原始证据文件。

## 5. 验收

- 同一 JSON 重复导入两次，`works` 数量不增加。
- 同一作品跨多个抓取版本出现，作品总账仍只有一条，版本关系增加。
- 同一作品历史转写既有失败又有成功，当前状态为成功。
- 服务中断后，已完成作品不重做，运行中作品回到队列。
- 新增作品和历史失败作品能进入下一批次，已完成和正在处理作品被跳过。
