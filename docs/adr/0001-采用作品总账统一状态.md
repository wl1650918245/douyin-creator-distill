# ADR-0001：采用作品总账统一状态

## 状态

已接受，2026-08-01。

## 背景

项目早期以抓取 JSON 和任务记录驱动页面。随着增量抓取、双通道转写、失败重试和多次历史任务增加，同一作品的状态散落在多个文件和表中，页面统计容易受查询范围和历史重复任务影响。

## 决策

保留不可变 JSON 作为原始证据，同时新增 SQLite 作品总账、处理状态、产物索引和任务检查点。`source_key + video_id` 是逻辑作品唯一键，页面与下游任务优先读取总账。

## 放弃的方案

1. 只保留一个最新 JSON：会丢失历史证据，无法审计。
2. 继续由页面合并任务记录：查询口径容易漂移，无法从数据库层保证唯一性。
3. 直接重写旧任务系统：迁移风险过高，可能破坏已有真实数据。

## 后果

### 正面

- 统一统计、去重、重试和恢复口径。
- 原始证据与当前状态分离。
- 新模块可以复用同一作品生命周期。

### 代价

- 需要从旧 JSON 和任务记录回填新表。
- 同一作品可能保留多个产物版本，需要明确当前版本和证据版本的区别。

### 风险控制

- 使用增加式迁移。
- 不删除旧表和文件。
- 所有回填操作幂等。
- 新状态读取失败时仍可退回旧任务记录排查。
