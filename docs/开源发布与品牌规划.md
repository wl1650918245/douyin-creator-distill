# 开源发布与品牌规划

更新日期：2026-07-28

## 一、公开定位

项目不应只被描述成“抖音爬虫”或“AI Agent”。推荐定位是：

> 把博主主页和收藏夹变成可检索知识、爆款规律、选题资产和可调用的博主智能体。

核心差异是“从内容目录到知识资产的本地闭环”，而不是单次下载或单条总结：

1. 获取博主主页、单条作品和本人收藏夹目录。
2. 审核并保留原始 JSON 证据。
3. 云端或本地 Whisper 转写。
4. 批量爆款拆解、选题生成和知识蒸馏。
5. 用 SQLite 保存任务、审计、订阅和产物索引。
6. 用户数据、账号 Profile 和密钥默认留在本机。

## 三、命名候选

### 已确认：CreatorDistill

- 中文展示名：创作者蒸馏台
- 仓库名：`douyin-creator-distill`
- 页面品牌：`CreatorDistill · 自媒体工作台`
- 优点：仓库名覆盖 Douyin 搜索关键词；产品品牌同时覆盖内容提取、知识蒸馏和博主智能体。
- GitHub 副标题：`Local-first creator intelligence agent for Douyin content, transcription, viral analysis and reusable creator personas.`

### 候选：ViralDistill

- 中文展示名：爆款蒸馏器
- 优点：传播直接，适合爆款拆解和选题场景。
- 缺点：弱化了收藏夹、知识库和普通内容归档能力。

### 候选：MediaAlchemy

- 中文展示名：内容炼金台
- 优点：品牌感强。
- 缺点：搜索时不能直接理解是创作者分析工具，需要副标题补充。

仓库搜索名与产品展示名分层：仓库使用 `douyin-creator-distill`，页面不反复强调平台
名称，保留未来扩展其他内容来源的空间。

## 四、README 首页结构

公开 README 应按以下顺序组织：

1. 品牌名、中文一句话价值、English tagline。
2. 一张无真实账号和本机路径的产品总览图或 20 秒 GIF。
3. “它解决什么问题”：批量目录、双通道转写、爆款拆解、选题、博主智能体。
4. 5 分钟快速开始：依赖诊断、示例配置、登录、启动。
5. 真实数据流图和风控边界。
6. 功能状态矩阵：已实测、自动化测试、尚未完成。
7. 本地隐私、安全与平台合规声明。
8. Roadmap、贡献指南、Issue 模板和 Release 下载。
9. 第三方来源与许可证。

禁止在 README 使用真实收藏夹、真实账号 Profile、本机用户名、API 密钥或无法复现的
“100% 抓全”“永不风控”等承诺。

## 五、公开发布门禁

当前仓库在以下条件全部满足前保持 Private：

- [x] 确认正式品牌名和仓库名。
- [x] 确认项目许可证。
- [x] 用空白演示环境重做截图，移除真实收藏夹和本机路径。
- [x] 提供 `SECURITY.md`、`CONTRIBUTING.md` 和 Issue 模板。
- [x] 从全新 Windows 目录执行一次冷启动安装验收。
- [x] 验证示例配置不包含真实凭据。
- [x] 验证 `runtime/`、SQLite、日志、模型和 Chrome Profile 不会进入 Git。
- [ ] 为首次公开版本打 `v0.1.0` 标签并写 Release Notes。

## 六、许可证建议

- `Apache-2.0`：已采用。允许商业使用和二次开发，同时包含明确的专利授权和 NOTICE 规则。
- `MIT`：最简单、传播阻力最低，但对专利和品牌边界约束更弱。
- `AGPL-3.0`：可要求网络服务修改公开源码，但会提高企业采用和贡献门槛。

第三方 Skill 和参考实现继续遵循各自许可证，来源和固定版本记录在
`THIRD_PARTY_NOTICES.md` 与 `skills/vendor-lock.json`。

## 七、首个公开版本范围

`v0.1.0` 只承诺已经有实测证据的本地单用户能力：

- 主页与收藏夹目录获取。
- JSON 审核、去重和有限恢复 Loop。
- 云端文本提取与本地 Whisper 双通道。
- 爆款拆解、选题顾问和博主智能体基础闭环。
- SQLite 任务、订阅、审计和产物索引。

多人登录、云端数据库、计费、跨机器同步和无人值守绕过平台验证不属于首发范围。
