# 账号体系规格

## 1. 目标

产品管理的是两个账号用途，而不是强制要求两个实体账号：

- `content`：内容采集身份，用于公开博主主页和公开单条作品。
- `favorites`：收藏夹身份，只用于当前登录账号自己的收藏夹。

收藏夹身份可以与内容采集身份共用同一个浏览器 Profile，也可以绑定独立 Profile。切换绑定方式不得改变抓取、转写和分析主流程。

## 2. 关键规则

1. 默认使用 `shared`：收藏夹身份复用内容采集 Profile，用户只需登录一次。
2. 用户可切换为 `independent`：两个身份使用不同 Profile、Cookie、状态文件和锁。
3. 共用模式下两个身份的 `effectiveProfileId` 相同，所有外部任务严格串行。
4. 独立模式下两个身份的 `effectiveProfileId` 不同，但第一版仍默认全局串行，不能把账号隔离误解为风控安全的并发许可。
5. 收藏夹只能读取收藏夹身份当前登录账号自己的内容，不尝试访问他人私有收藏。
6. 公开主页任务与收藏夹任务不能合并为一次抓取；标准 JSON 必须保留 `sourceMode`、`accountRole` 和 `profileId`。
7. 页面和日志不得显示 Cookie、浏览器 Profile 绝对路径或其他可复用凭据。
8. Profile、Cookie 和真实配置不进入 Git；示例配置可以提交。
9. 收藏夹目录沿用文件夹缓存和人工选择范围；公开博主关注任务使用审核基线执行追加式增量停止。

## 3. 本地配置

真实配置文件：

```text
config/account-profiles.config.json
```

示例结构：

```json
{
  "schemaVersion": "1.0",
  "favoritesBinding": "shared",
  "profiles": {
    "content": {
      "id": "content-collector",
      "profilePath": ""
    },
    "favorites": {
      "id": "favorites-owner",
      "profilePath": ""
    }
  }
}
```

`profilePath` 留空时使用产品管理的默认专用目录。账号中心 API 只返回逻辑身份、绑定关系、状态和 Profile ID，不返回该绝对路径。

## 4. 账号中心交互

侧栏只显示账号体系摘要：

```text
账号中心
采集：已验证 / 未验证
收藏夹：共用采集账号 / 独立账号
```

设置中心展示两个用途卡片：

- 内容采集账号：状态、最近验证时间、打开登录窗口。
- 收藏夹账号：共用/独立开关、状态、最近验证时间、打开登录窗口。

无法可靠读取平台昵称时，只显示“登录状态已验证”，不得虚构账号名称。

## 5. 接口契约

```text
GET  /api/account-profiles
POST /api/account-profiles
POST /api/account-profiles/:role/login
```

- `GET` 返回脱敏后的角色与状态。
- `POST` 第一版只允许修改 `favoritesBinding`。
- `login` 只接受 `content` 或 `favorites`，启动对应的可见登录窗口。

## 6. 任务路由

| 来源 | `sourceMode` | `accountRole` |
| --- | --- | --- |
| 公开博主主页 | `profile` | `content` |
| 公开单条作品 | `single` | `content` |
| 本人收藏夹 | `favorites` | `favorites` |

任务创建时保存当时解析出的 `profileId`。后续下载或转写沿用任务记录的角色，不能因为用户后来切换设置而静默换账号。

## 7. 分阶段交付

### 阶段 A：账号基础设施

- 双用途配置、共享/独立绑定、登录状态与账号中心 UI。
- 主页抓取显式使用内容采集身份。
- Whisper 下载沿用来源任务的账号身份。
- 品牌统一为“自媒体工作台”。

### 阶段 B：收藏夹适配器

- 枚举当前登录账号的收藏夹。
- 逐收藏夹分页获取作品并全局按 `videoId` 去重。
- 输出独立的收藏夹标准 JSON 和审核结果。
- 真实登录账号完成一次端到端回归后，才能将收藏夹标为“可用”。

阶段 A 完成不等于收藏夹抓取已经可用，页面必须明确展示该能力状态。

当前状态：阶段 A 已实现；阶段 B 尚未完成真实收藏夹回归。因此页面只能显示“我的收藏夹（待回归）”，后端收到收藏夹抓取请求时返回明确的 `409`，不会创建不可执行的假任务。

## 8. 参考项目与采纳边界

- `jiji262/douyin-downloader`：采纳“收藏夹属于当前 Cookie 登录账号”“收藏夹与公开作品分开运行”“登录态保存在本地”的产品边界。
- `TikHub/TikHub-Multi-Functional-Downloader`：参考多来源下载器的模块划分，不引入其服务依赖。
- 本地 `subprojects/douyin-downloader`：只作为已下载参考实现审阅，不作为本产品运行时依赖。

没有直接复制 Python 下载器，也没有把未经本机真实收藏夹验证的接口声明为已支持。收藏夹适配器完成后仍需用真实账号对账数量、去重结果、登录隔离和串行行为。

## 9. 验收标准

1. 默认配置下两个角色的 `effectiveProfileId` 相同。
2. 切换独立模式后两个角色的 `effectiveProfileId` 不同。
3. 账号接口响应中不存在 `profilePath`、Cookie 或环境变量值。
4. 两个角色分别生成状态文件；共用模式读取同一有效状态。
5. 主页抓取命令收到内容采集 Profile，但任务和日志不保存绝对路径。
6. Whisper Cookie 文件按 Profile ID 隔离。
7. 无效角色和无效绑定模式被拒绝。
8. 页面标题、侧栏品牌和重启提示统一使用“自媒体工作台”。
9. `npm run check`、账号配置测试、接口测试和浏览器 UI 检查通过。
10. 未完成真实收藏夹回归前，产品不得宣称收藏夹抓取可用。
