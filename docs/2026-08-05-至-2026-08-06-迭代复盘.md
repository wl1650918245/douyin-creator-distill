# 2026-08-05 至 2026-08-06 迭代复盘

## 1. 本轮目标

本轮不是继续增加孤立按钮，而是补齐两条可独立运行的产品能力：

1. 从“当前目录内筛选”升级为跨关注博主、收藏夹和已索引作品资产的智能检索。
2. 把转写失败从页面提示升级为可持久化、可判断、可阻断无效重试的服务端状态模型。

本复盘只记录已经落盘并完成验证的能力。尚未实现的图文 OCR 继续作为明确缺口保留。

## 2. 已完成改动

### 2.1 独立智能检索

- 左侧新增独立“智能检索”页面，不再依赖先打开某个博主目录。
- 支持搜索全部已索引资产，或只勾选一个或多个关注博主、收藏夹来源。
- 结果展示来源名称、作品标题、相关度、命中证据片段和原作品链接。
- 普通召回使用本地 Embedding，不调用外部模型；“精排前 20 条”仍是用户显式操作。
- 跨来源唯一键采用 `source_key + video_id`，防止不同来源中的同一作品互相覆盖。
- 精排标识从单一 `videoId` 改为跨来源安全的 `resultKey`。

真实证据：本机同时读取姜胡说和飞天闪客两个来源，共 726 条作品、3,520 个语义片段；跨来源 API 与 Playwright 页面查询均返回真实结果。

### 2.2 设置中心信息架构

- 设置中心拆为“系统与账号”和“模型与 API”两个子页签。
- 账号绑定、默认转写通道和本地依赖诊断归入“系统与账号”。
- 云端链接提取、本地语义模型和分析模型配置归入“模型与 API”。
- 切换页签只改变展示，不重置现有配置。

### 2.3 失败作品诊断与续接

- “继续剩余作品”改为先展示逐条失败原因，再选择云端优先或本地 Whisper 优先。
- 已成功作品继续保留，只对失败作品生成续接计划。
- 图文作品会明确说明本地 Whisper 不可用，不再把切换通道描述成一定可恢复。
- 页面只负责解释和选择，是否允许重试最终由服务端决定。

### 2.4 结构化错误分类与重试门禁

SQLite 的 `transcript_jobs` 新增：

- `error_class`：稳定的机器可读错误类型。
- `retryable`：当前错误是否允许再次执行。
- `terminal_reason`：不可重试时的最终原因。

当前分类规则：

| 错误类型 | 是否自动重试 | 处理方式 |
| --- | --- | --- |
| 网络超时、连接重置 | 是 | 在当前任务预算内重试 |
| QPS/短期限流 | 是 | 延迟后重试 |
| 配额耗尽 | 否 | 等待额度恢复或切换可用通道 |
| 配置、认证错误 | 否 | 用户修正配置或登录状态 |
| 图文无音轨 | 否 | 不进入 Whisper，等待 OCR 通道 |
| 云端确定性任务失败 | 否 | 保留证据，禁止同参数空转 |
| 未知错误 | 否 | 先复核和补分类，不默认重试 |

所有转写作品设置 6 次总尝试硬上限。页面、API 或其他调用方都不能无限增加 `max_attempts`。

真实证据：姜胡说剩余 7 条作品均为 `awemeType=68` 图文，旧逻辑下每条已经累计尝试 18 次。迁移后接口返回 `contentType=image`、`requiresOcr=true`、`retryable=false`；再次调用重试接口返回 400，尝试次数保持 18。

## 3. 问题复盘

### 3.1 为什么直到多次失败后才发现是图文

旧流程把“调用转写服务”放在“识别作品能力边界”之前。虽然原始 JSON 已经包含 `contentType=image`、`hasImages=true` 和 `awemeType=68`，但重试决策只检查错误文本，没有结合作品类型。

这导致系统知道 Whisper 不能处理图文，却仍把云端失败的图文当作普通失败项继续排队。

### 3.2 为什么会重复尝试 18 次

旧实现有两个叠加缺陷：

1. 未命中的错误默认视为可重试。
2. 每次人工点击重试都会把 `max_attempts` 设置为“当前次数 + 3”。

因此所谓“最大次数”不是全局上限，而是可不断向后移动的窗口。页面虽然显示失败，但服务端没有最终门禁。

### 3.3 为什么只修页面不够

禁用按钮只能阻止当前页面操作，不能阻止 API、脚本、服务重启恢复或未来的新入口重新提交同一任务。可靠性规则必须位于任务编排和持久化层，UI 只负责解释状态。

## 4. 本轮形成的工程规则

### 4.1 能力预检早于执行

每个处理任务在调用外部服务前，必须先根据作品类型进入能力矩阵：

```text
视频 -> 云端链接提取或本地 Whisper
图文 -> 云端首次尝试；失败后等待 OCR
缺少必要媒体地址 -> 阻断并记录缺失字段
```

不允许先执行多次，再根据失败结果猜测输入类型。

### 4.2 错误是数据，不是文案

`error_message` 用于给人阅读，`error_class` 和 `retryable` 用于程序决策。不得继续依靠不断扩大的正则表达式决定所有状态。

### 4.3 未知错误默认停止

未知错误自动重试可能消耗额度、触发平台风控并制造重复资产。新增错误必须先获得真实证据，再加入可重试白名单。

### 4.4 重试必须同时满足四个条件

1. 当前作品状态为失败或部分失败。
2. `retryable=1`。
3. `attempt_count` 未达到全局上限。
4. 新通道具备处理该作品类型的能力。

任何一个条件不满足，都必须拒绝执行并给出下一步。

### 4.5 状态迁移必须处理历史债

新增字段后不能只影响新任务。本轮服务启动时会回填历史确定性云端失败记录，使旧任务也受到新门禁约束。

### 4.6 实测证据必须覆盖失败路径

只验证成功搜索或成功转写不够。本轮验收同时检查：

- 真实跨来源索引规模和查询结果。
- 确定性失败只执行一次。
- 瞬时错误仍可续跑。
- 达到总次数上限后不能重试。
- 绕过页面直接调用 API 仍被拒绝。
