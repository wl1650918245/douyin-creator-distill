# 状态管理契约

## 1. 目的

本契约统一内容来源、作品、任务、尝试、处理状态和本地产物的身份与生命周期。页面不得再通过截取最近若干任务临时推断全局状态。

## 2. 核心对象

| 对象 | 唯一身份 | 责任 |
| --- | --- | --- |
| 来源 | `source_key` | 区分博主主页、收藏夹账号与收藏夹范围 |
| 作品 | `source_key + video_id` | 全局唯一作品总账，不随抓取批次变化 |
| 抓取任务 | `task_id` | 一次用户或调度器发起的目标 |
| 抓取尝试 | `attempt_id` | 一种执行策略的一次尝试 |
| 抓取版本 | `run_id` | 一份不可变 JSON 证据及其审核结论 |
| 处理状态 | `source_key + video_id + stage` | 作品在转写、拆解、蒸馏等阶段的当前状态 |
| 产物 | `artifact_id`，文件路径唯一 | JSON、Markdown、SRT、报告等本地文件索引 |
| 检查点 | `task_id + checkpoint_key` | 中断后继续所需的游标、作品和阶段状态 |

## 3. 不变量

1. 同一来源下，同一 `video_id` 在作品总账中只能存在一条。
2. 原始 JSON 是不可变证据。重新抓取创建新版本，不覆盖旧文件。
3. 只有审核通过的抓取版本才能推进作品总账和订阅基线。
4. 审核失败、登录失效、验证码、风控或字段缺失不得推进增量基线。
5. 已完成的处理状态不能被后续失败任务降级。
6. 新批次默认跳过已完成和正在处理的作品；历史失败作品可以重新进入待处理集合。
7. 批次状态由单作品状态汇总，不能反向覆盖单作品事实。
8. 每个页面统计必须来自作品总账或明确的任务批次，不得混用两种口径。
9. 文件索引只保存路径和元数据，不把 Cookie、API Key 或浏览器 Profile 路径写入证据文件。

## 4. 任务状态

```text
queued -> running -> waiting_for_audit -> waiting_for_user -> completed
                    \-> partial
running -> pausing -> paused -> queued
running -> interrupted_recoverable -> queued
running -> waiting_for_action
running -> failed
```

`waiting_for_action` 表示必须由用户处理登录、验证码、配置或配额问题。`interrupted_recoverable` 表示本地服务中断，但已经有可恢复检查点。

## 5. 作品处理状态

```text
not_started -> queued -> running -> completed
                         \-> failed -> queued
running -> paused -> queued
```

`completed` 是吸收状态。除非用户明确要求重新生成某种产物，否则后续任务不得将其降级或重复处理。

## 6. 待处理集合

每次提交转写、拆解或蒸馏前，统一计算：

```text
待处理 = 用户选择或新增作品
       + 历史可重试失败作品
       - 已完成作品
       - 正在排队或运行的作品
```

若计算结果为空，接口应明确返回“所选作品均已完成或正在处理中”，不得创建空任务。

## 7. 抓取恢复语义

抖音页面游标和 DOM 顺序可能变化，因此目录抓取不承诺从某个网页游标绝对原地继续。恢复时重新执行当前安全策略，并使用审核通过的基线和已持久化尝试进行 `video_id` 合并。转写任务则必须按单作品检查点精确继续。
