# 任务恢复与重试矩阵

| 场景 | 自动动作 | 最大次数 | 是否推进基线 | 用户入口 |
| --- | --- | ---: | --- | --- |
| 短暂网络错误、超时 | 当前策略有限重试 | 3 | 否，成功审核后才推进 | 查看实时进度 |
| 单作品下载或转写失败 | 标记单作品失败，批次继续 | 3 | 不影响目录基线 | 重试失败作品 |
| 服务重启 | `running` 单作品恢复为 `queued` | 不计为业务重试 | 否 | 自动继续或继续剩余作品 |
| Chrome Profile 被占用 | 等待串行执行位；确认死锁后清理项目锁 | 受任务 Loop 限制 | 否 | 查看失败原因 |
| 登录失效、验证码、风控 | 立即停止自动切换策略 | 0 | 否 | 重新验证登录 |
| `403`、`429`、平台限流 | 停止自动请求，进入人工处理 | 0 | 否 | 稍后重试 |
| 云端日配额用尽 | 混合模式切换本地 Whisper | 每作品一次路由切换 | 不适用 | 查看实际通道 |
| JSON 数量或必填字段异常 | 保留原始文件，禁止下游处理 | 可执行审核恢复 Loop | 否 | 查看待复核目录 |
| 增量任务中断 | 重新扫描近期范围，与旧基线按 ID 合并 | 按抓取 Loop | 否，审核通过后推进 | 继续抓取 |
| 转写批次暂停 | 当前作品完成后停止取下一条 | 不限 | 不适用 | 继续剩余作品 |

## 失败带入规则

新批次创建时，历史 `failed` 作品允许重新进入待处理集合；历史 `completed`、`queued` 和 `running` 作品默认跳过。失败原因、尝试次数和最后任务 ID 必须保留。
