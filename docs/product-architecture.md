# 产品架构

## 1. 产品边界

当前产品是单用户、本地优先的自媒体内容工作台。浏览器只提交用户意图和展示状态；Node 本地服务负责账号隔离、串行任务、SQLite 状态、文件读写和模型调用。产品不提前建设登录、租户、云数据库和计费系统。

## 2. 页面职责

| 页面 | 当前职责 |
| --- | --- |
| 内容工作台 | 输入主页、单条作品或“我的收藏夹”，获取目录，筛选作品并提交转写或拆解 |
| 任务中心 | 查看抓取、转写、拆解、选题、智能体和审稿任务的状态、日志与产物 |
| 关注与更新 | 管理关注博主和收藏夹，保存增量基线，定时发现新增内容 |
| 爆款拆解 | 使用已转写作品生成证据报告，并保留历史版本 |
| 选题顾问 | 从一份或多份爆款报告生成有来源、待核验的候选选题 |
| 博主智能体 | 聚合同一博主多条转写，生成可审计画像，并审阅新稿 |
| 设置中心 | 管理内容采集/收藏夹账号、转写通道、模型和本地依赖 |

## 3. 真实数据流

```text
平台来源
  -> 串行 Chrome 首轮抓取
  -> JSON 审核
  -> 未通过时执行一次 Chrome 恢复抓取并合并已有 JSON
  -> 仍未通过时使用内部接口补充目录数据
  -> 最终 JSON 审核
  -> 标准 JSON
  -> 用户筛选作品
  -> 云端链接提取 / 本地 Whisper
  -> 爆款拆解报告
  -> 选题顾问

同一博主的多条已转写作品
  -> 材料去重与覆盖判断
  -> 博主智能体画像
  -> 新稿审阅
```

JSON 是第一证据层。抓取完成不会自动消耗转写或模型额度。选题顾问只读已完成爆款报告；博主智能体至少需要 5 条同一博主的已完成转写，5 至 9 条只生成试用画像，10 条以上才达到建议线。

### 3.1 目录抓取 Loop

目录任务以“得到通过审核的标准 JSON，或明确停在可解释状态”为完成目标，而不是把一次进程退出当成任务结束。

1. `chrome_primary`：使用已配置的 Chrome Profile 抓取，不主动调用内部接口。
2. `chrome_recovery`：首轮审核未通过或发生可恢复错误时，再执行一次 Chrome 抓取；已有 JSON 不删除，按 `videoId` 合并。
3. `api_supplement`：两轮 Chrome 仍未通过时，才调用内部接口补充目录，并再次按 `videoId` 合并和审核。

每轮尝试写入 SQLite `task_attempts`，包括策略、状态、错误分类、产物路径和审核结果。网络短暂故障、字段缺失、数量或分页异常可以进入下一策略；登录失效、验证码、`403`、`429` 会立即进入 `waiting_for_action`，不继续重试，也不切换接口。当前第二轮 Chrome 是“重新抓取后合并”，尚未实现游标级断点续抓。

## 4. 存储分层

| 数据 | 位置 | 作用 |
| --- | --- | --- |
| 运行状态 | `.runtime/agent-state.sqlite` | 任务、进度、订阅、缓存和产物索引 |
| 原始目录 | `raw/douyin-analysis/<account>/` | 可追溯标准 JSON |
| 转写材料 | `raw/get-notes/`、`raw/transcripts/` | 云端原文和 Whisper 时间轴原文 |
| 爆款报告 | `analyses/viral-breakdowns/` | 单条或多条作品拆解 |
| 选题资产 | `analyses/topic-library/` | 带报告和作品 ID 的候选选题 |
| 博主智能体 | `agents/<douyin-id>/` | 画像与稿件审阅结果 |

SQLite 不是原始证据，不替代 JSON、Markdown、SRT 或 manifest。删除关注规则也不能删除历史资产。

## 5. 可信度门禁

- 所有外部抓取使用同一 Chrome Profile 串行执行，禁止两个进程争抢登录态。
- 模型配置和文本提取配置只保存在 Git 忽略的项目本地文件中。
- 选题必须引用输入报告和作品 ID，并显式列出拍摄前核验项与误用风险。
- 博主画像只能引用材料包中的完整 transcript ID 或 video ID；非法引用会使任务失败。
- 智能体审稿只借用结构和表达方法，不能把旧作品事实移植为新稿经历；缺失事实使用占位符。
- 抓取、转写和分析的失败都保留在任务中心，不做静默降级。
- 内部接口只作为两轮 Chrome 后的补充能力；验证码、登录失效和限流不会通过切换接口绕过。
- 选题顾问默认只使用同一博主的报告；只有用户主动开启跨博主对比模式，前后端才允许混合报告。
- 已完成的博主智能体默认进入查看、打开资产和稿件审阅，不重复生成同一成品。

## 6. 增量与缓存

收藏夹目录缓存 24 小时，用户可主动刷新。关注规则由本地服务每分钟扫描到期项，再加入唯一 Chrome 执行位；默认每日检查。增量检查只更新目录和基线，不自动转写、拆解或生成选题。
